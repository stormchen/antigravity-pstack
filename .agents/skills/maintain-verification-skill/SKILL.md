# Maintain a verification skill (維護專案驗證技能)

隨著應用代碼更迭，功能地圖與驗證腳本可能會產生漂移 (Drift)。本技能用於定期審查與更新專案的驗證技能（如 `verify-<app>/`），確保驗證步驟與真實應用保持一致。

## 產出狀態 (Outcomes)

- **clean**：所有功能均通過源碼與實機驗證，無須修改。
- **changed**：產出經過實機驗證的功能地圖與腳本修正。
- **blocked**：因特定阻礙無法完成覆蓋（明確說明阻礙原因）。

## 執行流程

0. **定位驗證技能**：在工作區中尋找現有的 `verify-*` 技能目錄。
1. **檢查功能地圖索引**：檢視 `features/README.md` 與所有子功能檔案，清理死連結與缺漏。
2. **源碼比對波次 (Source Wave)**：Main Agent 呼叫 `invoke_subagent` 平行派發多個 Subagent，各自審查單一功能檔案與對應源碼，標記可能的文件漂移點。
3. **整合分析**：合併各 Subagent 回報，整理出需實機驗證的重點清單。
4. **實機操作驗證 (Live Pass)**：執行 Doctor 健康檢查並依序驅動各功能，驗證修復後的腳本與功能地圖。
5. **分類處理**：文件描述過期則修正地圖；腳本失效則更新 harness 腳本；若為真實產品 Bug 則記錄問題並通報。
6. **更新與交付**：確認所有改動均通過實機測試後更新技能檔案。
