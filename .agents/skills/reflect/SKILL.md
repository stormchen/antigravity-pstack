# Reflect (對話復盤與經驗沉澱)

深入挖掘當前對話與任務執行過程中的經驗教訓，並將其沉澱轉化為對專案技能與規則的具體修改。

## 何時觸發

- 使用者要求「復盤」、「/reflect」或總結經驗。
- 一個複雜的任務（涉及多次工具調用）順利完成，其實現路徑值得固化為流程。
- Agent 在任務中遇到死胡同並摸索出正確路徑，此經驗具備通用價值。
- 使用者在任務中糾正了 Agent 的方法或提供了特定偏好。

## 執行流程

### 1. 取得當前會話與執行記錄
Main Agent 檢視當前對話與執行過程中的決策點、失敗嘗試與最終成功路徑。

### 2. 平行派發多角度審查 (Spawn Reviewers)
Main Agent 呼叫 `invoke_subagent` 工具，派發多個具備不同視角的審查 Subagent：
1. **判斷視角 (Judgment Lens)**：審查決策是否合理、是否存在過度設計或遺漏邊界。
2. **工具與流程視角 (Tooling & Process Lens)**：審查工具調用順序、自動化程度與重試效率。
3. **發散與創新視角 (Divergent Lens)**：探討是否有更簡潔、更根本的解決途徑。

### 3. 整合與分類 (Synthesize)
Main Agent 彙整所有審查回報，產出結構化清單：
- **Accepted (採納)**：明確有益且應立即沉澱為技能/規則的項目。
- **Rejected (否決)**：僅適用於單一特例或過於瑣碎的觀察（附上否決原因）。
- **Backlog (後續改進)**：屬於專案代碼庫或待辦清單層面的長期改善。

### 4. 結構化落實檢驗 (Structural Enforcement Check)
檢驗採納項目：若某項教訓能透過 Linter、型別約束、腳本或自動化測試更可靠地落實，優先轉化為結構化防護（遵循 **encode-lessons-in-structure** 原則）。

### 5. 呈現與應用 (Apply)
向使用者呈現採納與建議修改清單，經使用者確認後直接更新對應的 `SKILL.md` 或規則檔案。

## 輸出格式

- **應用的技能修改**：更新之技能檔案與修改重點。
- **新建的技能**：新建立的技能（如有）。
- **待辦與結構化改進**：建議加入專案 CI 或 Lint 的規則。
- **已過濾項目**：被否決的建議與原因。
